# PixelLab and comparable AI pixel-art tools/APIs for a photo-to-pixel-pet app (research as of 2026-10-13)

Research-environment note: the sandbox's egress policy blocked direct fetches of pixellab.ai, api.pixellab.ai, retrodiffusion.ai, scenario.com, huggingface.co, aseprite.org and most review sites, and reddit.com blocks Anthropic's crawler. Findings marked **[primary]** come from official pages (read through search-engine extracts) or from official GitHub repositories that were fetched in full; **[mirror]** means an official API's behaviour as documented by a third-party client whose author read the OpenAPI spec; **[secondary]** means review/comparison sites. Prices and limits were not re-verified on the live pages, so treat every number as "as published, undated unless stated".

## Key question 1: What exactly can PixelLab's API generate, at what sizes, cost per image, and can outputs be used commercially?

### Takeaway
PixelLab exposes a REST API (v1 paths `/v1/generate-image-pixflux`, `/v1/generate-image-bitforge`, `/v1/animate-with-skeleton`, `/v1/animate-with-text`, `/v1/rotate`, `/v1/inpaint`, `/v1/estimate-skeleton`, `/v1/balance`; v2 paths such as `/v2/create-image-pixflux`, `/v2/create-image-bitforge`, `/v2/image-to-pixelart`, `/v2/animate-with-text-v3`, `animate-with-skeleton-v3`) that is billed per call in USD at roughly $0.006–$0.013 per still image and $0.02–$0.04 per animation clip, with square-only sizes for rotation/animation (16/32/64/128/256). Its Terms of Service say the user owns the copyright of generations and may use them commercially, but also that PixelLab may retain uploaded input images for debugging, which matters for a privacy-first app.

### Cited Findings
**Endpoints and sizes**
- Official API marketing page lists `POST /v2/create-image-pixflux` (text-to-pixel-art, maximum area 400x400), `POST /v2/create-image-bitforge` ("apply custom art styles using reference images, maximum area 200x200", supports init images and forced palettes), inpainting with maximum area 200x200, `POST /v2/image-to-pixelart`, `POST /v2/animate-with-text-v3`, and a text-animation endpoint ("PixMiniMax", beta) that "requires a Tier 1 subscription or higher", is priced by generation time, supports 256x256 maximum and 4 to 40 frames. **[primary, via search extract]** — [PixelLab API page](https://www.pixellab.ai/pixellab-api)
- The authoritative references are the Swagger UI at `https://api.pixellab.ai/v2/docs`, the OpenAPI schema at `https://api.pixellab.ai/v2/openapi.json`, and an LLM-oriented reference at `https://api.pixellab.ai/v2/llms.txt` (per PixelLab's own `llms-full.txt`). The v2 docs are described as OpenAPI 3.1.0. **[primary, via search extract; not fetched]** — [PixelLab llms-full.txt](https://www.pixellab.ai/llms-full.txt), [api.pixellab.ai/v2/docs](https://api.pixellab.ai/v2/docs)
- Pixflux docs: "minimum area 16x16, maximum area 64x64 (>24x24 often higher quality)" is quoted on one docs page, while the "Create medium-extra large image (pixflux)" docs say the canvas minimum area is 32x32 and the maximum is 200x200 on the free tier, 320x320 on tier 1, 400x400 on tier 2+. The two docs pages conflict on the pixflux minimum/maximum; the tiered figures are the newer-looking ones. **[primary, via search extract]** — [Create image (pixflux) docs](https://www.pixellab.ai/docs/tools/create-image-flux)
- Older "style" tool docs say the reference-style canvas is limited to 80x80 for tier-1 accounts, conflicting with the 200x200 figure on the API page (docs page may be outdated). **[primary, via search extract]** — [PixelLab style tool docs](https://www.pixellab.ai/docs/tools/style)
- Full v1 parameter catalogue as mirrored by a third-party client that wraps the OpenAPI spec **[mirror]** — [animus-package-pixellab ENDPOINTS.md](https://raw.githubusercontent.com/railstracks/animus-package-pixellab/main/docs/ENDPOINTS.md):
  - `generate-image-pixflux`: `description`, `width`/`height` 16–400 each (area 32x32 to 400x400), `text_guidance_scale` (default 8), enums `outline`/`shading`/`detail`/`view`/`direction` ("weak guidance"), `isometric`, `no_background`, `init_image` + `init_image_strength` (API default 300), `color_image` (forced palette), `seed`.
  - `generate-image-bitforge`: 16–200 per side, area ≤200x200; `style_image` + `style_strength` 0–100 (default 0, "50 is balanced"); `negative_description`; `coverage_percentage` 1–100; `init_image`; `inpainting_image` + `mask_image` (white = regenerate); `skeleton_keypoints` (JSON frames of `{x,y,label,z_index}`) with `skeleton_guidance_scale` (default 1); "sizes other than 16/32/64 reduce quality, and the API returns a warning".
  - `animate-with-skeleton` (v1): width/height each one of 16, 32, 64, 128, 256; `reference_image` (character on transparent background) required; exactly 3 skeleton frames in; "typically 4 frames" out; longer animations by re-running with the next 3-pose window and passing prior frames as `init_images`.
  - `animate-with-text` (v1): fixed 64x64 only; `description`, `action`, `reference_image` required; always generates 4 frames; `start_frame_index` to window.
  - `rotate`: `from_image`; width/height each one of 16, 32, 64, 128; `from_view`/`to_view` (default `side`), `from_direction`/`to_direction` (defaults `south`→`east`), `view_change`/`direction_change` in degrees, `image_guidance_scale` default 3, optional `init_image`/`mask_image`/`color_image`.
  - `inpaint`: 16–200 per side, area ≤200x200; `inpainting_image` + `mask_image` required; `text_guidance_scale` default 3.
  - `estimate-skeleton`: input 16–256 px per side, returns `data.keypoints` with 18 labels (NOSE, NECK, shoulders, elbows, hips, knees, eyes, ears...).
  - `balance`: returns `data.balance_usd`.
- `animate-with-skeleton-v3` (beta, "needs a tier 1+ subscription"): 3–15 frames per request; every frame is drawn from one reference image; one 18-joint skeleton per frame with x/y as 0–1 fractions; requires `first_frame_keypoints` (the skeleton the reference already shows) and "a mismatch quietly costs transparency/color accuracy"; cost 3 frames = 2 generations, 8 frames = 3, 15 frames = 4. Issue opened 2026-09-20, shipped in pixelkiln v0.67.0 on 2026-09-26. **[mirror, developer notes]** — [gfargo/pixelkiln issue #189](https://github.com/gfargo/pixelkiln/issues/189)
- Official JS SDK `@pixellab-code/pixellab` (MIT, Node 16+, default base `https://api.pixellab.ai/v1`) documents `generateImagePixflux` (`description`, `imageSize`, `negativeDescription`, `textGuidanceScale`, `noBackground`, `outline`, `shading`, `detail`) and `generateImageBitforge` (`description`, `imageSize`, `styleImage` base64, `styleStrength`, `noBackground`) plus `getBalance`; lists skeleton animation, text animation, inpainting and rotation as supported but undocumented in the README; 3 stars, 6 commits. **[primary]** — [pixellab-code/pixellab-js](https://github.com/pixellab-code/pixellab-js)
- Official hosted MCP server at `https://api.pixellab.ai/mcp` (HTTP transport, `Authorization: Bearer <token>`) offers `create_character` (4 or 8 directional views), `animate_character` (`character_id`, `animation` e.g. walk/run/idle), `create_tileset` (Wang tilesets, `lower`/`upper`), `create_isometric_tile` (`description`, `size`, example 32). - A photo/render-to-pixel-art route exists: pixelkiln's `pixelate` utility "converts a photo or render to pixel art via Image to Pixel Art Pro Flash, at 6 generations". PixelLab's docs page for this tool says charges "vary with the request and processing time", "pricing is provisional", "the credit price follows the source image, and square images cost the most". **[mirror + primary via extract]** — [gfargo/pixelkiln README](https://github.com/gfargo/pixelkiln), [Image to pixel art docs](https://www.pixellab.ai/docs/tools/image-to-pixel-art)

### Inferences
- For a 41x34 to ~80x70 pet, the cost-relevant endpoints are bitforge (32x32–64x64 ≈ $0.007), image-to-pixelart (64x64 ≈ $0.006) and animate-with-text-v3 (≈ $0.02–0.04 per 4–16-frame clip). A full pet (one base + idle/walk/sleep/eat clips) is on the order of $0.10–$0.20 per user at list price, before failed/retried generations.
- Rotation and animation endpoints only accept square power-of-two-ish sizes (16/32/64/128/256), so a 41x34 or 80x70 canvas must be padded to 64x64 or 128x128 and cropped afterwards.
- Because PixelLab's ToS allows retention of input images and the image-to-pixel-art route requires uploading the pet photo, using PixelLab for the user-photo step is incompatible with "photos stay on the phone". It remains usable for assets that contain no user data (furniture, room themes, tilesets) generated at development time.
- The tier names and generation counts are inconsistent across review sites and PixelLab's own docs pages conflict on pixflux limits, which suggests plans were revised during 2025–2026; the live pricing page should be checked before quoting numbers.

### Gaps
- Could not fetch the official pricing page, the OpenAPI schema or `llms.txt`; the exact tier-to-plan mapping, documented rate limits and the prices for rotate/inpaint/skeleton endpoints are unconfirmed.
- Whether free-tier accounts get API access at all (vs. "pay-per-generation API" requiring a subscription) is not stated in any source found; PixMiniMax text animation and skeleton-v3 explicitly require Tier 1+.
- No source states how long retained input images are kept or whether API users can opt out.

## Key question 2: How to call PixelLab (auth, request/response, SDKs, MCP) and comparable APIs

### Takeaway
PixelLab is a plain HTTPS JSON API with a secret token (Bearer), base64-encoded PNG inputs and base64 image outputs, plus an official JS SDK, an official hosted MCP server and an Aseprite extension; Retro Diffusion has a similarly simple `X-RD-Token` JSON API (v2 is queue-and-poll) and its own MCP server; Scenario and Leonardo are general image APIs with pixel-art models/presets layered on.

### Cited Findings
**PixelLab**
- Auth: secret key from pixellab.ai/account, sent as Bearer; JS SDK reads `PIXELLAB_SECRET`; base URL `https://api.pixellab.ai/v1` (v2 under `/v2`). Egress is only to `api.pixellab.ai`. **[primary/mirror]** — [pixellab-js](https://github.com/pixellab-code/pixellab-js), [animus-package-pixellab](https://github.com/railstracks/animus-package-pixellab)
- Image inputs are base64; responses expose `image` (`dataUrl`, `saveToFile()`); animation endpoints return multiple frames (`_f1`..`_fN`); errors: 401 (token), 402 (balance/top-up), 422 (validation detail), 429 (retry later), 529 (service overloaded). **[mirror]** — [ENDPOINTS.md](https://raw.githubusercontent.com/railstracks/animus-package-pixellab/main/docs/ENDPOINTS.md)
- Official MCP server `https://api.pixellab.ai/mcp` with Bearer token; setup via pixellab.ai/vibe-coding. Third-party MCPs: PixelLab Forge MCP (MIT), PixelLabRat (local desktop app + MCP). **[primary/secondary]** — [pixellab-mcp](https://github.com/pixellab-code/pixellab-mcp), [PixelLab Forge MCP](https://glama.ai/mcp/servers/rabbitcannon/pixellab-forge-mcp), [mcpservers.org listing](https://mcpservers.org/servers/pixellab-code/pixellab-mcp)
- Community CLIs/wrappers that encode current endpoint behaviour: pixelkiln (MIT, 495 commits, generators `map`, `pixflux`, `1dir`, `tiles`, `character` with "four PixelLab engines", `imagePro`, `imageProFlash`, `terrain`, `isometricTile`, `objectPro`, `uiAsset`, `uiElement`, `vfx`; utilities `unzoom`, `pixelate`, `font`, `estimate-skeleton`, `skeleton-preview`), pixellab-cli. **[mirror]** — [gfargo/pixelkiln](https://github.com/gfargo/pixelkiln), [protonspy/pixellab-cli PR #33](https://github.com/protonspy/pixellab-cli/pull/33)
- The ToS restricts programmatic use to the official API (no scraping the web app). **[primary via extract]** — [PixelLab ToS](https://www.pixellab.ai/termsofservice)

**Retro Diffusion** **[primary: official examples repo, fetched in full; page footer © 2026]** — [Retro-Diffusion/api-examples](https://github.com/Retro-Diffusion/api-examples)
- Base `https://api.retrodiffusion.ai/v2` (v1 still supported, "no retirement plan"); header `X-RD-Token: rdpk-...` (max 5 keys per account); optional `Idempotency-Key` on paid POSTs; MCP at `https://mcp.retrodiffusion.ai/mcp` with `Authorization: Bearer`.
- `POST /v2/inferences` returns a `task_id`; poll `GET /v2/inferences/tasks/{task_id}` (`pending`/`running`/`succeeded`/`failed`); examples poll every 2 s. Result fields: `base64_images` (PNG, GIF for animations), `output_urls` (with `upload_outputs: true`; signed URLs last 15 min), `balance_cost`, `remaining_balance`, `model`.
- Request fields: `prompt`, `prompt_style` (selects model/style), `width`/`height` (12–512 overall; per-style tighter), `num_images` (clamped, up to 16; animations 1), `seed`, `input_image` (raw base64 RGB, no data-URI prefix) + `strength` (0–1, default 0.75), `reference_images` (RD Pro only, up to 9), `input_palette`, `remove_bg`, `tile_x`/`tile_y`, `frames_duration` (4/6/8/10/12/16), `return_spritesheet`, `upscale_output_factor`, `check_cost` (free dry run).
- Size families: RD Pro 12–256 px; RD Plus/RD Fast 64–384 px; advanced animations 32–256 (rotate multiples of 8); some animations fixed at 32/48/64/128; tilesets 16–32 px.
- Pricing: `rd_fast` $0.03/image; `rd_plus`, `rd_mini`, tile styles $0.06; `rd_pro` $0.18 (`fps_weapon` $0.25); animations $0.07 (some $0.25); advanced animations $0.14 (custom_action/subtle_motion $0.25, rotate $0.10); tilesets $0.10; edit tools $0.18 paid / $0.01 background remover and colour style transfer / several free; Pixel Fixer free. Failed generations are refunded; credits cannot be bought through the API (prepaid USD balance, packs from $5 per the homepage). — also [retrodiffusion.ai homepage](https://retrodiffusion.ai/)
- Third-party directory listings quote RD Fast at ~$0.015 (older/lower than the official $0.03). **[secondary, conflicting]** — [mcpservers.org Retro Diffusion MCP](https://mcpservers.org/servers/retro-diffusion/retro-diffusion-mcp)
- Retro Diffusion models are also available inside Scenario (RD Plus, RD Tile, RD Animation; RD Animation styles `four_angle_walking`, `walking_and_idle` only 48 px, `small_sprites` only 32 px, `vfx` 24–96 px; `inputPalette` and image-to-image `image` parameters) and on Replicate (`rd-fast`, `rd-plus`: width/height 16–384, default 256, `strength` 0–1 default 0.8). **[primary, via extracts]** — [Scenario docs: Retro Diffusion](https://docs.scenario.com/docs/third-party-model-generation-retro-diffusion), [Scenario help: RD essentials](https://help.scenario.com/articles/4202673551-retro-diffusion-models-the-essentials), [Replicate rd-plus](https://replicate.com/retro-diffusion/rd-plus/versions/f13b1ce52e2a0e68cb8f5c2987b492e10958c10b701b908921fca003fb9e97fa/api)

**Scenario** **[primary via extracts]**

- Subscriptions (third-party, conflicting): Starter $15/mo, Pro $45/mo, Teams $75/mo (CostBench, June 2026); another guide says $15/mo with 50 credits/day. — [CostBench](https://costbench.com/software/ai-3d-generation/scenario-gg/), [Cinevva guide](https://app.cinevva.com/guides/ai-pixel-art-generators)

Custom style/character training "most models perform well with 10 to 20 high-resolution images". — [Scenario commercial use](https://help.scenario.com/can-i-use-scenario-to-generate-images-for-commercial-projects), [Scenario FAQ](https://help.scenario.com/articles/1129045411-frequently-asked-questions-faq), [Scenario Train](https://www.scenario.com/features/train)

- Pixelicious (photo-to-pixel web converter: palette, grid size 32–256 px, denoise, background removal, PICO-8/Game Boy palettes) was "made by Hugo and is joining Scenario"; listings disagree on whether it is free. **[secondary]** — [AlternativeTo](https://alternativeto.net/software/pixelicious/about), [Korben review](https://korben.info/en/pixelicious-transform-photos-into-pixel-art.html)

**Leonardo.ai** **[secondary only]**
- API billed separately from the consumer subscription, pay-as-you-go "Production API ($5 non-expiring starter credit)"; Image Guidance suite (ControlNet, Style Reference, Character Reference); v2 endpoint adds structured style/content/character/image-to-image references. Sources conflict on whether free-tier outputs are commercial (one says yes but public; another says non-commercial, paid from $12/mo). No pixel-art-specific model or styleUUID was found. — [apiframe Leonardo API guide](https://apiframe.ai/guides/leonardo-ai-api-guide), [pricepertoken Leonardo pricing](https://pricepertoken.com/leonardo-ai-pricing), [magetop free generators](https://www.magetop.com/blog/free-ai-image-generators-commercial-license/)

### Inferences
- All of PixelLab, Retro Diffusion, Scenario and Leonardo are cloud-only: every call sends the input image to the vendor. None offers an on-device SDK.
- Retro Diffusion's `check_cost`, idempotency keys, refunds-on-failure and explicit error-code table make it the most "production-shaped" API of the group for a mobile backend; PixelLab's API is simpler (synchronous, USD balance) but its documented error surface is thinner.
- Since both vendors recommend proxying through your own server (PixelLab tokens are secrets; Retro Diffusion keys are account-level), an app would need a Supabase edge function or similar in front of either API rather than embedding keys in the APK/IPA.

### Gaps
- No official PixelLab rate-limit numbers, SLA or documented latency; a community MCP's test suite retries 8 times with 10–15 s delays on rate limits, which is only a hint. — [search extract referencing deepwiki pixellab-mcp](https://deepwiki.com/pixellab-code/pixellab-mcp/3.1-image-generation-tools)
- Retro Diffusion's own Terms of Service (ownership/commercial use of outputs) could not be found; an itch.io comment thread shows users asking the question without a visible answer. — [astropulse itch comments](https://astropulse.itch.io/retrodiffusion/comments)
- Leonardo's official pixel-art preset ID and API price list were not found.

## Key question 3: Can any tool produce a consistent character across poses/animations (idle, walk, sleep, eat) from one reference, and how good is the consistency?

### Takeaway
Both PixelLab (reference-image anchoring + skeleton/text animation + rotation) and Retro Diffusion (up to 9 reference images on RD Pro, animation models trained on sprite sheets) are designed for this, but the only hands-on evidence found is mixed: one developer reported PixelLab's skeleton route "does not return correct frames" (Sept 2026) with PixelLab recommending text-animation v3 instead, and no independent benchmark of identity consistency exists.

### Cited Findings
- PixelLab's v1 skeleton animation draws 4 frames from 3 posed skeletons and one transparent-background reference image; longer clips are chained by passing prior frames as `init_images`; text animation (v1) is 64x64 only, 4 frames per call with `start_frame_index` windowing. **[mirror]** — [ENDPOINTS.md](https://raw.githubusercontent.com/railstracks/animus-package-pixellab/main/docs/ENDPOINTS.md)
- Skeleton-v3 (beta): 3–15 frames from one reference, requires accurate `first_frame_keypoints` or transparency/colour accuracy degrades; developer notes relay PixelLab's description of the result as "steadier identity and colours than a plain template loop" (vendor claim). **[mirror]** — [pixelkiln issue #189](https://github.com/gfargo/pixelkiln/issues/189), [pixelkiln PR #224](https://github.com/gfargo/pixelkiln/pull/224)
- A pixellab-cli commit (2026-09-16/17) states "the skeleton route does not return correct frames", "validated against PixelLab", and that "PixelLab recommends Animate with text V3". **[mirror, single developer report]** — [pixellab-cli PR #33](https://github.com/protonspy/pixellab-cli/pull/33)
- An extended-search extract of developer notes says skeleton-v3 "costs 2–4 generations and takes 3–5 minutes per direction" and "requires a Tier 1 plan". **[mirror, unverified attribution]** — [pixelkiln PR #224](https://github.com/gfargo/pixelkiln/pull/224)
- pixelkiln's `character` generator: "4- or 8-direction base, poses, and loops ... Cost is 1 per base, 10–25 per pose, and 1 per template loop per direction. Mirrored loop directions are free." **[mirror]** — [gfargo/pixelkiln](https://github.com/gfargo/pixelkiln)
- PixelLab's marketing: tools "adapt to your reference images to maintain visual consistency across all your sprites". **[primary, vendor claim]** — [pixellab.ai](https://www.pixellab.ai/)
- Retro Diffusion: "Up to 9 reference images lock a character in place or match your game's existing art exactly" (RD Pro); its MCP docs suggest generating once with RD Pro, then passing the output as a reference in follow-ups; a Runware write-up says its FLUX-based model maintains consistency "rather than relying on image-to-image approaches ... through prompting". **[primary vendor claim / secondary]** — [retrodiffusion.ai](https://retrodiffusion.ai/), [mcpservers.org RD MCP](https://mcpservers.org/servers/retro-diffusion/retro-diffusion-mcp), [Runware blog](https://runware.ai/blog/retro-diffusion-creating-authentic-pixel-art-with-ai-at-scale)
- Retro Diffusion's RD Animation styles are fixed-size (48 px walking/4-angle, 32 px small sprites) and accept optional reference images. **[primary via extract]** — [Scenario help: RD essentials](https://help.scenario.com/articles/4202673551-retro-diffusion-models-the-essentials)
- A competitor's blog asserts two approaches exist in 2026, "trained on multi-frame sprite-sheet datasets (the Retro Diffusion rd-animation approach)" vs "reference-image pinning on a general diffusion model" (PixelLab), claiming the former "always wins on identity consistency" (vendor opinion, no data). **[secondary, biased]** — [Sorceress blog](https://sorceress.games/blog/spin-up-an-ai-sprite-sheet-generator-browser-based)
- A 2026 comparison recommends "Retro Diffusion for the best-looking base sprites, PixelLab for rotations and animation"; Retro Diffusion's Aseprite extension uses smaller models than the website and excludes animation ("DO NOT buy the extension if you are trying to get the same results as the website"). **[secondary + vendor]** — [GameDev AI Hub: RD vs PixelLab](https://gamedevaihub.com/retro-diffusion-vs-pixellab/), [astropulse itch page](https://astropulse.itch.io/retrodiffusion)
- The only user-ish comment found: an itch.io poster "uses PixelLab and can reproduce a similar style, though with less detail". **[secondary]** — [pixelslime99 itch comments](https://pixelslime99.itch.io/buildingforge-urban-edition/comments)

### Inferences
- Both vendors can, in principle, produce idle/walk/sleep/eat for a pet from one 64x64 reference, but "sleep" and "eat" are not template loops (templates named are walk/run/idle), so they would go through text-described actions (PixelLab animate-with-text-v3 / Retro Diffusion `custom_action` at $0.25) where identity drift is likeliest.
- Both pipelines are humanoid-centric: PixelLab's skeleton has 18 human joints (nose, neck, shoulders, elbows, hips, knees, eyes, ears); a quadruped pet does not map onto it, so skeleton animation is a poor fit for dogs/cats/rabbits regardless of consistency.
- Consistency is probabilistic and should be validated per generation (e.g. palette distance to the base sprite, alpha-silhouette checks) with retries; budget for 2–3x list price.

### Gaps
- No independent, quantitative consistency benchmark of PixelLab vs Retro Diffusion vs Scenario was found; reddit.com is closed to this crawler so r/PixelArt / r/gamedev sentiment could not be sampled.
- No source tested either tool on animals/quadrupeds or on chibi proportions.

## Key question 4: Which approach fits a 41x34 to ~80x70 chibi pet made from a user photo, on-device if possible?

### Takeaway
No AI pixel-art generator surveyed runs on the phone; the only on-device options are classic pipelines (segment → posterize/quantize to a palette → nearest-neighbour downscale → optional dither → edge/outline), which is essentially what PawPixel's `SpritePipeline`/`Chibi` already does, or running a Stable Diffusion 1.5 + pixel-art LoRA on-device via MediaPipe/Core ML at ~8–15 s per image with >2 GB peak memory and no pixel-grid guarantees.

### Cited Findings
**Cloud tools that accept a real photo (require upload)**
- PixelLab `image-to-pixelart` (64x64 ≈ $0.006) / "Image to Pixel Art Pro Flash" (6 generations) converts photos; bitforge accepts `init_image` + `style_image`. Input images may be retained under ToS §3.4. **[primary via extracts / mirror]** — [PixelLab API page](https://www.pixellab.ai/pixellab-api), [pixelkiln](https://github.com/gfargo/pixelkiln), [PixelLab ToS](https://www.pixellab.ai/termsofservice)
- Retro Diffusion `input_image` + `strength` (img2img) and `remove_bg`; outputs retrievable 24 h, request metadata 30 days. **[primary]** — [Retro-Diffusion/api-examples](https://github.com/Retro-Diffusion/api-examples)
- Pixelicious: browser tool with palette, 32–256 px grid, denoise and background removal; ownership moving to Scenario. **[secondary]** — [AlternativeTo](https://alternativeto.net/software/pixelicious/about)

**On-device / offline options**
- Apple `ml-stable-diffusion` (Swift package, iOS 16.2+/17 for 6-bit compression; A14/M1+): SD 2.1-base 512x512, 20 steps ≈ 7.9 s on iPhone 14 Pro Max, 10.4 s iPhone 13 Pro Max, 15.4 s iPhone 12 Pro Max; SDXL 768x768 ≈ 31 s on iPhone 15 Pro Max; peak memory "can exceed 2 GB"; 4-bit palettization cuts peak RAM up to 75%; SDXL 4.5-bit ≈ 1.46 GB on disk; ControlNet supported for SD 1.x/2.x only; LoRA not mentioned (would need to be merged before conversion). SD 1.5 benchmarks not given. **[primary]** — [apple/ml-stable-diffusion](https://github.com/apple/ml-stable-diffusion)
- Google MediaPipe Image Generator (Android, experimental, Oct 2023): on-device SD v1.5-architecture models, "as quickly as ~15 seconds on higher end devices", supports LoRA weights for style injection. **[primary, 2023]** — [Google Developers blog](https://developers.googleblog.com/en/mediapipe-on-device-text-to-image-generation-solution-now-available-for-android-developers/)
- `nerijs/pixel-art-xl` (SDXL LoRA, CreativeML OpenRAIL-M, 13.4k downloads, updated Nov 2023): recommended 8 steps, guidance 1.5 with LCM LoRA, "requires downscaling images 8 times using Nearest Neighbors for pixel-perfect results"; settings advice conflicts across sources. **[secondary; HF page unreachable]** — [PromptLayer pixel-art-xl](https://www.promptlayer.com/models/pixel-art-xl), [Scenario pixel-art-xl](https://www.scenario.com/models/pixel-art-xl)
- Classic photo-to-pixel libraries (all client-side, portable to Kotlin):
  - Pixel It (giventofly/pixelit, MIT, ~1.8k stars, changelog 2025-11-05): `scale` 0–50, `palette` array of RGB, `maxWidth/maxHeight`; `pixelate()`, `convertPalette()`, `convertGrayscale()`. **[primary]** — [giventofly/pixelit](https://github.com/giventofly/pixelit)
  - Image-to-Pixel (Tezumie, library MIT / app Apache-2.0): Floyd–Steinberg, 2x2/4x4 Bayer, Ordered, Clustered 4x4, Atkinson dithering with 0–100 strength; Lospec palettes by slug or custom hex; `resolution: 'pixel'` for true pixel output. **[primary]** — [Tezumie/Image-to-Pixel](https://github.com/Tezumie/Image-to-Pixel)
  - ComfyUI PixelArt Detector palette converter: PIL `Image.quantize` or OpenCV k-means; dithering none/Floyd–Steinberg/Bayer 2–16; stray-colour cleanup. **[secondary]** — [RunComfy node docs](https://runcomfy.com/comfyui-nodes/ComfyUI-PixelArt-Detector/PixelArtDetectorConverter)
  - Pillow recipe (contrast boost → posterize → nearest-neighbour downscale → quantize with Floyd–Steinberg against adaptive/hardware palette → upscale); note "quantizing after the downscale keeps dithering aligned with the final pixel grid". **[secondary]** — [hermes-agent pixel-art skill](https://tessl.io/registry/skills/github/NousResearch/hermes-agent/pixel-art)
- Desktop/offline editors: PixelOver (Deakcor; Steam $19.99 list / itch $30 list with sales to ~$13.80; Early Access) does image-to-pixel-art conversion with pre-adjustment, palette generation/import, pixel-perfect outlines, plus bone rigging/IK animation and spritesheet export. **[primary store pages]** — [PixelOver on Steam](https://store.steampowered.com/app/1762550/PixelOver/), [PixelOver on itch](https://deakcor.itch.io/pixelover)
- Aseprite ($19.99 one-time; source public under a proprietary EULA that allows self-compiled personal use and commercial art but forbids redistribution): `--batch`/`-b`, `--script`, `--save-as` with `--filename-format`, `--shell` REPL; community pattern `aseprite -b sprite.aseprite -script export.lua`; `app.command.ExportSpriteSheet` needs a sprite open; `app.isUIAvailable` / `app.params` for CLI-only scripts. Purchases moved to Paddle in June 2026. **[primary via extracts]** — [Aseprite CLI docs](https://www.aseprite.org/cli/), [Aseprite FAQ](https://community.aseprite.org/faq), [Aseprite blog 2026-06-30](https://blog.aseprite.org/2026/06/30/new-website-account/), [Steambase price](https://steambase.io/games/aseprite/price)
- Mobile editors: "Pixel Studio for pixel art" (iOS) imports PNG/JPG/GIF/BMP/TGA/PSD/EXR and can "apply palettes to images" / "grab palettes from images"; Pixen imports from Photos. No photo-to-sprite automation documented. **[primary store pages]** — [Pixel Studio (App Store)](https://apps.apple.com/app/id1404203859), [Pixen](https://apps.apple.com/app/pixen-pixel-art-editor/id1161880215)

### Inferences
- On-device diffusion is technically possible (Core ML / MediaPipe) but a 41x34 sprite would still be produced at 512 px and downscaled 8–16x, giving no control over pixel count, palette or silhouette, at 8–15 s and >2 GB RAM per attempt; that is a poor trade against the deterministic procedural `Chibi` approach.
- The best privacy-preserving architecture is a hybrid: keep the user-photo path fully on-device (segmentation/palette extraction into `PetLook`, procedural drawing), and use PixelLab or Retro Diffusion only at development time to batch-generate room themes, furniture (`Decor.Furniture`), tilesets and wall/floor variants, which contain no user data and are commercially usable under both vendors' stated terms (PixelLab explicit; Retro Diffusion unconfirmed).
- For dev-time asset generation at 16–32 px tiles and ≤64 px props, Retro Diffusion `rd_plus` ($0.06) or PixelLab bitforge ($0.007) are cheap; Aseprite `--batch` + Lua can post-process (palette-lock, trim, sheet) into the app's PNG format.

### Gaps
- No published measurement of on-device SD 1.5 + pixel-art LoRA quality at small sprite sizes, nor of CoreML model-on-disk size for SD 1.5 (only SDXL figures found).
- Whether Pixelicious runs its conversion client-side (no upload) is not stated.

## Key question 5: What are typical latencies and failure modes?

### Takeaway
Official numbers exist only for Retro Diffusion (edit tools 20–40 s, polling every 2 s, 429 with `Retry-After`, 502/503/504 provider errors, automatic refunds) and for on-device SD (8–31 s); PixelLab's documented failure surface is 401/402/422/429/529, with community reports of skeleton animation taking minutes and sometimes returning wrong frames.

### Cited Findings
- Retro Diffusion: `inpainting`/`outpainting`/`image_edit` take about 20–40 s; Low-Poly jobs 1–5 min (up to ~15 min at size 256); examples poll every 2 s; Pixel Fixer limited to 10 requests/min per token; base64 bodies capped at 900,000 bytes; 429 includes `Retry-After`; error codes `inference_failed` (502, retry once), `provider_busy` (503, wait minutes), `provider_timeout`/`request_timeout` (504, retry); 409 on idempotency-key reuse with different inputs; failed generations refunded. **[primary]** — [Retro-Diffusion/api-examples](https://github.com/Retro-Diffusion/api-examples)
- PixelLab errors: 401 token, 402 balance/top-up, 422 validation, 429 retry later, 529 service overloaded; bitforge warns when skeleton sizes are not 16/32/64; skeleton animation "identical input frames can produce fewer" than 4 frames; animate-with-text always generates 4 frames regardless of `n_frames`. **[mirror]** — [ENDPOINTS.md](https://raw.githubusercontent.com/railstracks/animus-package-pixellab/main/docs/ENDPOINTS.md)
- PixelLab skeleton-v3: mismatched `first_frame_keypoints` "quietly costs transparency/color accuracy"; reported 3–5 minutes per direction; one developer found the route "does not return correct frames" (Sept 2026). **[mirror]** — [pixelkiln #189](https://github.com/gfargo/pixelkiln/issues/189), [pixellab-cli PR #33](https://github.com/protonspy/pixellab-cli/pull/33)
- PixelLab PixMiniMax text animation is "priced by generation time" (so cost varies with latency). **[primary via extract]** — [PixelLab API page](https://www.pixellab.ai/pixellab-api)
- PixelLab's ToS §2.1 reserves the right to change features, usage limits and pricing "if maintaining the current offering becomes economically untenable". **[primary via extract]** — [PixelLab ToS](https://www.pixellab.ai/termsofservice)
- Review sites say the free tier queues "slower generations" and Tier 2 buys a "priority queue", implying queueing delays on lower tiers. **[secondary]** — [knowara review](https://knowara.com/ai-tools/image/pixellab-review/)
- On-device: Core ML SD 2.1 512x512/20 steps 7.9–18.5 s across iPhone 12–14; SDXL 27–116 s; `reduceMemory` adds up to 2 s (SD) or "significant overhead" (SDXL); apps may need the Increased Memory Limit entitlement to avoid crashes. MediaPipe ~15 s on high-end Android (2023). **[primary]** — [apple/ml-stable-diffusion](https://github.com/apple/ml-stable-diffusion), [Google Developers blog](https://developers.googleblog.com/en/mediapipe-on-device-text-to-image-generation-solution-now-available-for-android-developers/)
- Conversion-quality failure mode for classic converters: "the quality of the conversion depends heavily on the input image's resolution and complexity". **[secondary]** — [Pixelicious listing](https://www.futuretools.io/tools/pixelicious)

### Inferences
- A user-facing flow that calls PixelLab or Retro Diffusion for a pet (still + 3–4 clips) would take tens of seconds to several minutes and needs a background job + retry/refund handling; neither is suitable for a synchronous onboarding screen.
- Vendor-side changes (beta endpoints, provisional pricing, "usage limits may change") are a product risk: the asset pipeline should be a build-time script with cached outputs checked into the repo, not a runtime dependency.

### Gaps
- No official PixelLab latency, rate-limit or uptime figures found; no third-party uptime monitoring found for either vendor.
- No data on PixelLab/Retro Diffusion behaviour with non-square inputs beyond the documented size constraints.
